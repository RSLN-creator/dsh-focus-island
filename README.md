# 惜时岛 · dsh-focus-island

[**English**](README.en.md) | 简体中文

DeepSeek Harness（DSH）Web UI 插件：右上角一个**灵动岛形态**的计时与状态面板。

它解决的不是「怎么计时」，而是**「我又坐着看 AI 干活看了半小时」**：只要你还待在这个页面
（可见且有焦点），计时就一直走，不管你在读、在打字还是草稿没发；你一发送消息，计时立刻作废重来。
到点用暖色提醒告诉你「你已在这个没有对话的窗口里停留 N 分钟」。

没有构建框架、没有 npm 依赖、不改官方任何 DOM：Client 半是一个官方 `__ModuleLoader__` 动态
bundle，只往官方 `shell.overlay` 座位注册一个浮层。

---

## 功能

### 计时

| 能力 | 说明 |
|---|---|
| 停留计时 | 条件：页面可见 ∧ 窗口有焦点。打字、草稿非空、模型在生成都**不影响**计时——待在这个会话里就是在计时 |
| 提醒间隔 | 1 – 180 分钟，默认 25；数字框可直接输入 1–180 的任意整数，± 按 5 分钟步进，另有 5/15/30/45/60/180 预设 |
| 到点提醒 | 展开显示「你已在这个没有对话的窗口里停留 N 分钟」+ 暖色警示 + 一次性脉冲 |
| 跳过 | **必须二次确认**：第一次点击进入确认态，文案明写「确认你知道这段时间仍被消耗」；确认后停表直到你下次发送消息。跳过后卡片显示「本轮已跳过」和实际计入的分钟数，不再复用提醒文案 |
| 结束提醒 | 到点后的提醒卡上也有「跳过」，同样二次确认——语义是「这一轮我看过了」，确认后本轮不再自动重复，直到下次发送。文案与计时中的跳过区分（「结束本轮提醒？」） |
| 发送即重置 | composer 内 Enter（非 Shift）或主发送按钮点击 → 清零重计 |
| 自动再来 | 到点提醒 **N 分钟**没人处理就自动再计时一轮并再次提醒；默认 2 分钟（0–10 可调，0 = 关闭），点了岛上的任何按钮即视为已处理、本轮不再自动重复 |
| 输入不暂停 | 打字 / 草稿非空只记录到状态里，不再冻结计时；把没写完的消息放一会儿不算「离开」 |
| 切窗口即暂停 | 页面隐藏或窗口失焦 → 暂停，回来从冻结值继续；这正是插件想鼓励的「去干别的」 |
| 持久化 | 计时进度与偏好写 `localStorage`。**同一进程内的刷新**继续原来那一轮（包括已结束/已跳过的那一轮）；**关掉软件再开**算冷启动，从零重新计时，不会把昨天的提醒卡重新摆出来（判据是每 5 秒写一次的心跳 `pulseAt`，超过 2 分钟即视为新一次启动） |
| 桌面通知 + 提示音 | 到点时发系统通知并响提示音；两者**默认开启**，可在设置里分别关闭 |
| 严格模式 | **设置 → 外观与其他**里有一个「严格模式」开关。开启后到点**整屏遮罩**：只剩官方像素鲸，以及**所有正在运行 / 正在等你回答的会话**——每行是它自己的「深度求索中，用时 19分25秒 ···」。没有会话在跑时不是空着，而是官方口径的一行「空闲中，已停留 3分02秒」。此模式下没有跳过、没有重新计时、没有收起，也不会自动再来；右下角两个出口：「跳过本轮」重计 5 分钟并保留严格模式，「退出所有严格模式」重计 5 分钟并关掉严格模式。**有提问待回答时遮罩自动让位**（见下） |

### 严格模式

开关在**设置 → 外观与其他**里（文字就是「严格模式」四个字，右侧跟一个开关控件），默认**关**。
它不在卡片正面、也不在收缩胶囊上：一个能把整块屏幕盖住的开关不该待在你工作时随手能点到的地方。

开启后，倒计时结束时不是弹出提醒卡，而是把整个界面盖住：

| 元素 | 内容 |
|---|---|
| 主视觉 | 官方像素鲸 —— 直接用 `@deepseek-ai/dsh-client-ui-brand-official` 的 137 帧图集（`lib/assets/breach-atlas.webp`，逐字节未改），按官方渲染器的方式解码绘制。两种官方填充交替播放：**先点阵像素鲸**（官方第一次点击的样式），下一轮换成代码字填充 |
| 会话列表 | **正在运行的会话 + 正在等你回答的会话**，当前会话排第一。每行右边是**这个会话自己的用时**，用官方那句「深度求索中，用时 19分25秒 ···」的格式；等你的那行是「等待你的回答，已等 5分12秒」 |
| 没有会话时 | 一行**「空闲中」** + 「已停留 3分02秒」，从遮罩出现的那一刻一直走。以前这里会凭空造一行「未命名会话 · 深度求索中，用时 1秒」——读起来像有个会话正在生成，其实什么都没在跑 |
| 出口 | 右下角两个按钮：**跳过本轮** / **退出所有严格模式** |

严格模式的硬约束（都由测试守着）：

1. **不能自动跳过计时。** 岛上的跳过按钮、重新计时按钮在遮罩期间都不提供，`Escape` 也不会关掉它。
2. **不会自动再来。** 普通模式下「到点 N 分钟没人理就自动再计时一轮」会把 `finished` 变回 `counting`，那等于把遮罩从眼前收走；严格模式下这条自动再来被显式关掉（`verify/strict-smoke.mjs` 用同一场景对照着证明：strict 关时仍然自动再来）。
3. **两个出口，范围不同。** 「跳过本轮」关掉这次遮罩并从 5 分钟重新计时、**严格模式保持开启**；「退出所有严格模式」同样重计，并**把严格模式关掉**。一个按钮只能猜你想要哪个，猜错要么把你困在刚想退出的模式里，要么悄悄关掉了你还想保留的保护。

`finished` 才会遮罩：`skipped` 是你自己已经结束的一轮，不遮。

#### 有提问时遮罩必须让位

模型的提问卡（`ask_user_question`，也包括需要你确认的审批）渲染在对话的 composer 座位里——
**在遮罩下面，永远不在它上面**。所以遮罩一旦盖住整屏，你既看不见问题，也没法回答，那一轮就卡死在那里。
这是真实踩过的坑：助手在等一个回答，人只看见像素鲸。

现在按官方 `useSessionStatus.pendingInteraction` 判断（侧栏小红点、composer 里的提问卡读的是同一个事实）：

| 情形 | 行为 |
|---|---|
| 遮罩期间出现待回答 | **自动让位**：走「跳过本轮」同一条出口（关遮罩、重计 5 分钟、严格模式保持开启），让提问露出来。**不会替你回答**，也不会替你跳过问题 |
| 不在遮罩期间出现待回答 | 岛上给一次提醒（系统通知 + 提示音，受通知/提示音开关控制），卡片里多一行「有提问待回答」，收缩胶囊把系统时间换成「待回答」，状态点变琥珀 |

「让位」用的是严格模式里唯一允许的软出口，不是后门：规则还在（5 分钟后再来），只是这一轮先让提问通过。

**每个会话的用时是怎么来的**：官方那句「用时」读的是该会话自己的 turn 时间轴
（`turn.start.time`），而 `shell.overlay` 座位拿不到它——官方 `useSessionStatus` 只给
`running / pendingInteraction / completionUnread`。所以插件在 `running` 的**上升沿**记录起点，
并把它写进偏好，刷新不会把还在干活的会话打回 1 秒。这是测量，不是估算：同一份数据在
`verify/strict-smoke.mjs` 里会随时钟推进从 1 秒长到 19 分 25 秒。

等待中的会话单独记一条 `pendingInteraction` 的上升沿（偏好键 `pendingStarts`）：它已经不在生成了，
用 `running` 的起点会把它等的时长算长。两套起点都写进 `localStorage`，刷新后继续走。

**计时是活的**：遮罩自己有 1 秒脉冲（`maskClock`）。到点之后状态机不再发通知，墙钟又只有 30 秒一跳，
所以以前遮罩上的数字看起来是冻住的——现在每行的用时、以及「空闲中，已停留 …」每秒都在涨。

### 形态与外观

- **收缩态**：单胶囊 —— 状态色圆环（绿=计时中 / 琥珀=暂停 / 红=到点）+ 倒计时 + 系统当前时间，
  第二行是 CPU / GPU / 内存 / GPU 温度 四条**裸彩条**（无标签、无百分比，长度与颜色就是读数；
  具体数值见鼠标悬停或读屏标签，展开卡片里才是带名称与数字的完整仪表）。
- **展开态**：卡片 —— 顶部状态点 + 「惜时岛」+ 右上角收起；居中大号倒计时；
  动作行（跳过 / 设置，两个同规格图标按钮）；**本机资源**区；**设置**区（设置展开时资源区位置不动，只在它下面长出来）。
- 尺寸档位：收缩态「紧凑 / 标准 / 大」三档（默认标准 1.2×），设置里可调。
- 底色：**不透明纯色**，取官方表面令牌 `--dsw-alias-bg-layer-1` —— 浅色即纯白 `#fff`、深色即 `#232324`，
  与 DSH 自身的层表面一致。没有毛玻璃、没有 `backdrop-filter`、也没有不透明度设置：岛浮在会滚动的对话之上，
  背景模糊会逼合成器每帧重读并重算身后内容，表现就是滚动卡顿（见「时间是怎么算的」旁的性能说明）。
- 颜色：计时中的圆环、进度条、两个开关统一用 DeepSeek 蓝（`state-business-primary`）；暂停琥珀、到点红只作状态色。
- 语言：岛内中文 / English 可切换（不影响整个 DSH 的语言）。
- 主题：只用 `--dsw-alias-*` 语义令牌，明暗主题自动跟随；动效为 `cubic-bezier(.34,1.3,.64,1)`
  弹簧，`prefers-reduced-motion` 下把时长令牌整体归零（**不是**逐条 `!important`），**没有任何常驻循环动画**，静止时页面回到空闲。
- 设计令牌：字号、动效时长、圆角都声明在 `.dfi-root` 上一次，规则里只读 `var(--dfi-fs-*)` /
  `var(--dfi-dur-*)` / `var(--dfi-radius-*)`，圆角能对上官方的直接用 `--dsw-radius-*`。
  `node audit-tokens.mjs` 保证不再出现字面量（改前实测：24 处字号、5 处圆角、24 处时长）。
- 字号：全岛一套八档 —— **10 / 11 / 12 / 12.5 / 13 / 14 / 15 / 38**。
  10 是紧凑控件（紧凑/标准/大、中文/English、两个「测试」、预设 chip），15 是收缩态时钟，
  38 是展开后的单一大号倒计时；这三档以前是硬编码，现在也在字阶里。
- 圆角：官方 `--dsw-radius-sm/md/xl` 直接用；只有资源条（2px 级）另立 `--dfi-radius-track`。
- 几何：所有视图共用同一条 header 基线（左内边距 16px、状态点 + 「惜时岛」+ 右上收起），
  正文与动作行也在同一条 16px 竖线上；提醒卡不再各自加一层水平内边距。

### 资源监视（扩展）

- 数据来自 **Host 半**：CPU/内存用 `node:os` 差分，GPU 利用率 / GPU 温度用 `nvidia-smi`。
- 页面每 **5 秒**轮询同源路由 `/dsh-focus-island/resources`（页面隐藏时暂停）；Host 端 CPU/内存最多每 1 秒刷新一次，GPU 利用率与温度每 **15 秒**刷新一次（`nvidia-smi` 要起子进程，实测 4 秒会把一个核心的 2.5% 永久烧掉）。
- 收缩态与展开态都显示；数值按阈值换色：占用 <60% 绿 / 60–85% 琥珀 / ≥85% 红；
  温度 <60 / 60–80 / ≥80；缺失在展开卡片里显示 `--`，在收缩态里是变淡的空条。
- **口径是整机，不是本会话**（原因见下方限制）；温度是 **GPU 温度**，不是 CPU 温度。

## 安装

本插件按 DSH 官方 profile bundle 方式安装（不要手写 profile 的 `package.json` / `cordis.patch.yml`）：

```
plugin_manager { action: "install_bundle", target: "D:\\9_Code_Workspace\\dsh-focus-island" }
```

- Client 半：刷新页面生效。
- Host 半（资源路由）：随 bundle 挂到运行中的 Loader。若安装时未生效，把 bundle 关一次再开一次
  （`plugin_manager set_bundle enabled:false` → `true`）即可热加载，**不需要重启 dsh**。
- 卸载：`plugin_manager { action: "remove_bundle", target: "dsh-focus-island" }`。

## 开发

```
package.json            bundle 清单（dsh.bundle + dsh.client）
cordis.patch.yml        一行 insert：dsh-focus-island
build.mjs               把 lib/{core,widget,monitor-client,client-main}.js 拼成 lib/client.js
lib/core.js             专注状态机（纯逻辑、可注入时钟、可单测）
lib/widget.js           灵动岛视觉（React createElement，无 DSH 依赖）
lib/monitor-client.js   资源轮询（fetch + 退避 + 可见性暂停）
lib/client-main.js      DOM 观测（composer/焦点/布局/拖动）、持久化、shell.overlay 注册
lib/host-monitor.js     可选：CPU/GPU/内存/温度采样 + 同源 HTTP 路由
lib/index.js            Host 半入口（惰性加载 host-monitor，失败不影响倒计时）
```

改任意 `lib/*.js` 源文件后必须重新生成 bundle：

```powershell
node build.mjs          # 生成 lib/client.js（源：core / notify / whale-atlas / whale / widget / monitor-client / client-main）
node build.mjs --check  # 校验 lib/client.js 是否与源一致
node build-atlas.mjs    # 由 lib/assets/breach-atlas.webp 生成内嵌图集 lib/whale-atlas.js（base64 data URL）
```

验证（全部 node 直跑；`render-smoke.mjs` 需要本机 Chromium/Edge，没有则**跳过并说明原因**）：

```powershell
node verify/core.test.mjs          # 计时状态机（44 项）
node verify/monitor.test.mjs       # 资源采样/轮询（17 项）
node verify/widget-smoke.mjs       # 视觉树 / CSS 令牌 / 布局结构 / 严格模式开关与遮罩 / 空闲行与提问让位（422 项）
node verify/whale.test.mjs         # 官方像素鲸：图集几何、帧序列、两种填充、通道语义（20 项）
node verify/notify-smoke.mjs       # 通知/提示音开关与触发（默认开、关掉就静默）
node verify/auto-repeat-smoke.mjs  # 忽略提醒后的自动再来（2 分钟后重启一轮；点击即取消）
node verify/strict-smoke.mjs       # 严格模式：真的抑制自动再来；会话名取自窗口标题
node verify/integration-smoke.mjs  # 伪浏览器 + 伪 Cordis：装配、右栏跟随、topInset、打字不停表、发送重置、会话行口径
node verify/render-smoke.mjs       # 真实 Chromium：遮罩整屏、鲸两轮都画出来、退出按钮在右下角（明暗两套）
node verify/mutation.mjs           # 反向变异：把实现改坏，确认上面这些断言真的会失败
node audit-tokens.mjs              # 设计常量漂移：规则里不得再出现字面量字号/圆角/时长
```

`render-smoke.mjs --screenshots <dir>` 会同时存下明暗两套截图与几何读数。

`verify/mutation.mjs` 值得单独说：本轮首次跑它时，它立刻暴露了**三处无效断言**——
只读源码字符串的检查（「文件里有 `+ 1`」）在行为被改坏后依然通过。现在鲸的通道语义改用
**合成图集**测：一张只有绿色通道描述剪影的图，读错通道就画不出东西；一张绿色全零、alpha 全不透明的图，
读 alpha 就会画出整张图。改坏实现，这两条必然失败。

`integration-smoke.mjs` 值得单独说：它把生成后的 `lib/client.js` 丢进伪造的 `window/document`，
按官方 `__ModuleLoader__` 协议取工厂、用伪 ctx 调 `apply`，再断言：

- `shell.overlay` 恰好一个占位（id `dsh-focus-island`）；
- 伪 `[data-rightbar-col]` 宽 420 → 组件收到 `rightInset = 420`；
- 伪官方 header 高 76 → 组件收到 `topInset = 86`（76 + 10 间距）；
- 往伪 composer 写字并按键 → 快照仍是 `counting` 且 1.1 s 后 `elapsedMs` 上涨（打字不停表）；派发非 Shift Enter → 归零重计。

## 时间是怎么算的（以及为什么有时感觉忽长忽短）

- **用时间戳差分，不是每秒累加**：内部只记「当前计时片段的起点」，每次刷新用
  `now - 片段起点 + 已冻结时间` 求已计时。浏览器后台节流、掉帧都不会让时间漂移，也不会重复触发。
- **只有离开页面才冻结**：窗口失焦或页面隐藏会**冻结**（不是清零），回来从冻结值继续；
  打字、草稿非空、模型在生成都不再冻结——待在会话里就是在计时。所以「你实际坐着的 10 分钟」
  和「表走的分钟数」只有在切窗口时才会不相等。
- **发送 = 清零重来**（不是接着走）；跳过之后停表，直到下次发送。
- **显示的是剩余时间**；到点后卡片显示「已停留 N 分钟」。
- **自动再来**：提醒弹出后 N 分钟（默认 2，可设置 1–60）没有人点任何操作，会自动清零再计时一轮，到点再次提醒；
  **严格模式下这条关闭**——自动把 `finished` 变回 `counting` 就等于替用户把遮罩收走。
- 提醒期间你点岛上的任何按钮（重新计时 / 跳过 / 知道了 / 收起）都算已处理，本轮不再自动重复。
- **刷新页面**：正在走的进度会保留并重新锚定（离线期间不计费）；
  到点或跳过的**终态也会恢复**——刷新后仍显示「你已停留 N 分钟」/「本轮已跳过」，不会从 0 重开计时，
  也不会把刚处理过的提醒再弹一次。只有下次发送消息才开启新一轮。

## 通知与声音

被动停留计时到点时，插件会同时尝试两个通道：

- **桌面通知**：用浏览器 `Notification` API 发一条系统通知（带页面图标，同一类提醒用 tag 合并，不会叠一屏）；
  默认开启时，页面**第一次点击**会自动申请一次系统通知权限（浏览器的权限弹窗只能由用户手势触发）；设置里的开关行在未授权时提示「需要允许系统通知」。
- **提示音**：Web Audio 现场合成的上行「叮咚」短音，**不打包音频文件**；
  播放结束会挂起 AudioContext，不会让音频设备一直占着。

两个开关在 **设置 → 通知**里，**默认都开启**，可以只留一个；每行下面有「测试」按钮，可以当场试。
桌面端（Electron）里系统通知本身静音，声音由插件自己的提示音负责。

> 通知/声音的封装与音型参考了 [`@dingyi222666/dsh-session-notification`](https://github.com/dingyi222666/dsh-session-notification)
> （BSD-3-Clause）：同一套受控的 `Notification` 包装与 Web Audio 播放器，裁到本插件需要的两类提醒。

## 资源与隐私

- 只在浏览器 `localStorage` 里存三类数据：`dsh-focus-island:v1:prefs`（间隔/外观/语言）、
  `dsh-focus-island:v1:state`（计时快照）。
- 不向任何远端上报；资源数据只在本机 Host 采样、同源返回给页面。
- 路由要求同源凭据（页面内 `fetch(..., { credentials: 'same-origin' })`），外部请求返回 401。

## 已知限制

1. **「本次会话单独的资源占用」做不到。** 模型推理发生在远端 API，浏览器与 Host 都只有整机视角，
   没有「本会话 CPU/GPU」这种可测量量。所以资源区显示**整机**并明确标注「本机资源」，不伪造占比。
2. **GPU 利用率与 GPU 温度依赖 `nvidia-smi`。** 没有 NVIDIA 卡或命令不在 PATH 时这两项显示 `--`。
   CPU 温度需要额外拉 WMI/驱动，本插件不做。
3. **模型「正在生成」是 DOM 启发式**（composer 里是否有「停止」按钮、会话区 1.5 s 内是否有文字变动）。
   官方客户端没有暴露流式状态事件；该状态只影响圆点颜色，不参与计时。
4. **切到别的窗口不扣时间**，这是设计意图。若想「只要页面开着就算」，改
   `lib/client-main.js` 中 `createPresenceSeat().sync()` 的 `visible` 判定即可。
5. 计时精度：显示到秒，内部 tick **1 s** 用时间戳差分，后台标签节流也不会漂移
   （1 s 是界面能显示的最快分辨率，`core` 本身也把订阅合并到整秒）。
6. **严格模式的会话名与用时来自官方会话存储。** 名字取 `useSessions` 的 `title`
   （空白会话显示「未命名会话」）；用时由插件在 `running` 上升沿自行记录 —— 官方
   `useSessionStatus` 只给 `running / pendingInteraction / completionUnread`，那句「用时」在官方是读每个
   会话自己的 turn 时间轴，overlay 座位看不到。所以刷新页面后，正在运行的会话会从记到的起点继续，
   而不是从 1 秒重来。
7. **严格模式的像素鲸是内嵌的官方图集**（`lib/whale-atlas.js`，由 `build-atlas.mjs` 从 `lib/assets/breach-atlas.webp`
   生成 base64 data URL）而不是走 `/plugins/<pkg>/assets/...` 路由：后者要求插件资源路由已经挂上、且改完要重启 DSH，
   而遮罩必须在任何 profile 下都能画出鲸。代价是 `lib/client.js` 从约 200 KB 涨到约 437 KB。
8. **`render-smoke.mjs` 需要本机 Chromium/Edge**；没有就跳过并打印原因，不当作通过。它借用
   `dsh-webcode-bridge` 里已装的 `playwright-core`，不给本仓库新增依赖。
